# Whale Reminder · 产品原型文档

> 版本 v0.1 · 2026-11-11
> 形态：Windows 桌面宠物 + 待办管理 + AI 接入（MCP）

---

## 1. 一句话定位

**一个会盯着你干活、并且能听 AI 指挥的桌面宠物。**

不是待办清单。待办清单的核心问题是——**你不需要它的时候，它不存在；你需要它的时候，你已经忘了**。

---

## 2. 它解决的真实问题

传统待办工具的三次死亡：

| 死因 | 表现 | 本产品的解法 |
|---|---|---|
| **不存在感** | 藏在浏览器标签页里，三天不打开 | 桌宠常驻桌面，永远在视野里 |
| **记录成本** | 想到一件事，要打开 app、点新建、打字、选时间 | 跟 AI 说一句"提醒我周五交周报"，AI 直接写进去 |
| **无人追问** | 写下来的那一刻就已经忘了，到期弹个通知，点掉继续拖 | 到点不只是提醒，还会**追问"做到哪了"**，并根据回答调整节奏 |

三者构成一个闭环：

```
  随口说一句  ──→  AI 通过 MCP 写入  ──→  桌宠记住
       ↑                                      │
       │                                      ▼
   AI 复盘进度  ←──  用户回答/敷衍  ←──  到点提醒 + 追问
```

**这个闭环里，桌宠负责"存在感"，AI 负责"零成本记录"，追问机制负责"闭环"。三者缺一不可。**

## 3. 目标用户与场景

### 用户画像

单人使用、Windows 桌面、每天开机 8h+、已经有 AI 助手习惯（Claude Desktop / Cursor / Cherry Studio）的人。典型是开发者、设计师、独立工作者。

### 场景 A：AI 侧录入（最高频）

> 在跟 AI 讨论需求时，AI 说"这个改动需要你先确认接口文档"。
> 用户："那提醒我明天上午弄。"
> AI 调用 `create_task`，写入待办，`due_at` 设为明天 10:00。
> 桌宠立刻冒泡："记住了，明天 10 点提醒你确认接口文档。"
> **用户全程没有打开任何界面。**

### 场景 B：到点追问（核心差异）

> 15:00，桌宠冒泡：“写周报，还差 40 分钟到点，开始了吗？”
> 三个按钮：`已完成` / `进行中` / `还没开始`
> 用户点"还没开始" → 桌宠记下来，20 分钟后换个说法再问一次。
> 如果连续两次"还没开始"，它不再高频打扰，改为明早提醒，但会在面板上把这条标红。

### 场景 C：被动查看

> 用户想知道今天还有什么没做，双击桌宠展开面板。
> 一眼看到"今天 3 项、逾期 1 项"，不用切窗口、不用打开浏览器。

### 场景 D：AI 复盘（进阶）

> 晚上用户问 AI："我今天进度怎么样？"
> AI 调用 `get_today_brief`，拿到完成 4 项、逾期 1 项、追问 3 次未响应。
> AI 回答："今天完成了 4 件，'整理季度数据'已经逾期两天，追问了三次都没动，要不要拆成更小的步骤？"

## 4. 三种界面态

整个产品只有三种界面，互相切换，不并存。

### 4.1 桌宠态（默认，99% 的时间）

```
                    ┌────────────────┐
                    │    ╭──────╮    │
                    │   ╱  ●  ●  ╲   │      176 × 176 透明窗口
                    │  │    ▽     │  │      无边框 · 置顶 · 不占任务栏
                    │  │  ╭───╮   │  │      仅角色本体接收鼠标
                    │   ╲ ╰───╯  ╱   │      可拖拽，位置持久化
                    │    ╰──────╯    │
                    └────────────────┘
                    屏幕右下角 · 站立姿态
```

角色是 **Q 版鲸鱼女仆娘**（深蓝渐变长发、鲸鳍耳饰、女仆围裙、蓝色鲸尾），立绘素材与状态映射见 [04-pet-character-design.md](04-pet-character-design.md)。默认状态使用 `front.webp`。

**行为规格**

| 交互 | 响应 |
|---|---|
| 鼠标移入 | 上浮 4px + 快速眨眼一次（`react`），0.25s 缓动 |
| 单击 | 冒一个迷你气泡，显示"今天还剩 N 项" |
| 双击 | 展开待办面板 |
| 拖拽 | 切 `side` 立绘，随移动方向倾斜 ±6°，松手回正并持久化位置 |
| 右键 | 托盘同款菜单（打开面板 / 暂停提醒 / 设置 / 退出） |
| 无操作 30min | 进入 `idle`，呼吸周期放缓 |
| 系统时间 23:00–07:00 | 切 `sleep` 立绘，不再主动冒泡 |

### 4.2 气泡态（提醒与追问）

```
              ┌────────────────────────┐
              │ 写周报                 │
              │ 距截止还有 25 分钟     │
              │                        │
              │ [ 已完成 ]  [ 稍后 ]   │
              └───────────┬────────────┘
                    ┌─────┴─────┐
                    │   ◠   ◠   │   ← 切 working 立绘，气泡弹出
                    │     ▽     │
                    └───────────┘
```

气泡是**唯一打断用户的东西**，所以必须克制：

- 位置跟随桌宠，不遮挡桌宠本体
- 8 秒无操作自动收起（`ask` 类气泡不自动收，等用户回答）
- 同一时刻**最多一个气泡**，多个提醒排队
- 气泡出现时桌宠轻微上浮，不发出声音（除非用户开启）
- 点"稍后" → 5 / 15 / 30 分钟三选一（默认 15）

### 4.3 面板态（管理）

```
┌──────────────────────────────────────────────────────┐
│ Whale Reminder                            ─   □   ×   │
├──────────────────────────────────────────────────────┤
│  + 添加待办           搜索...            设置        │
├──────────────────────────────────────────────────────┤
│                                                      │
│  今天 · 3 项                                          │
│                                                      │
│  ○  写周报                    14:00 提醒    剩 25m   │
│  ○  回复产品邮件              已追问 2 次            │
│  ●  买咖啡                    已完成                 │
│                                                      │
│  本周 · 逾期 1 项                                     │
│                                                      │
│  ○  整理季度数据              逾期 2 天      !       │
│                                                      │
├──────────────────────────────────────────────────────┤
│  桌宠运行中 · AI 已接入 · 共 12 项                    │
└──────────────────────────────────────────────────────┘
```

**面板只做四件事**：看、加、改、完成。不做日历视图、不做看板、不做番茄钟。**任何增加"需要停留"的功能都是对这个产品的背叛。**

## 5. 桌宠状态机

状态由 Rust 侧驱动，前端只负责渲染。

```
                      ┌──────────────┐
         鼠标移入 ───→│    react     │←─── 鼠标移出
                      │   上浮眨眼    │
                      └──────┬───────┘
                             │
        ┌────────────────────┼────────────────────┐
        │                    │                    │
        ▼                    ▼                    ▼
   ┌─────────┐         ┌──────────┐        ┌──────────┐
   │  idle   │         │  remind  │        │  think   │
   │ 待机站立 │         │  提醒中   │        │  追问中   │
   └────┬────┘         └────┬─────┘        └────┬─────┘
        │                   │                   │
        │  23:00–07:00      │  用户响应          │  用户回答
        ▼                   ▼                   ▼
   ┌─────────┐         ┌──────────────────────────┐
   │  sleep  │         │  celebrate / idle        │
   │ 闭眼休眠 │         │  完成撒花 / 回到待机      │
   └─────────┘         └──────────────────────────┘

   ┌─────────┐
   │  drag   │  拖拽时覆盖所有状态，松手回 idle
   └─────────┘
```

**状态优先级**（同时满足时取高）：`drag` > `remind` > `think` > `react` > `idle` > `sleep`

**立绘映射**

| 状态 | 立绘 | 状态 | 立绘 |
|---|---|---|---|
| `idle` / `react` | `front.webp` | `think` | `thinking.webp` |
| `remind` | `working.webp` | `sleep` | `sleep.webp` |
| `drag` | `side.webp` | `celebrate` | `playing.webp` |

> `remind` 切到 `working` 立绘——角色“坐下来开始干活”，本体比 `front` 小约 25%，该跳变已确认可接受，切图时用交叉淡入 + 下移缓解（见形象设计文档第 4 节）。

素材处理、眨眼坐标与动画规格见 [04-pet-character-design.md](04-pet-character-design.md)。

## 6. 核心流程

### 6.1 添加待办（两条路径）

**路径 A：AI 录入（推荐路径）**

```
用户对 AI 说 → AI 调 create_task → MCP 写库 → 桌宠收到变更 → 冒泡确认
```

**路径 B：手动录入**

```
双击桌宠 → 面板 → "+ 添加待办" → 单行输入框
                                      │
                     ┌────────────────┴────────────────┐
                     ▼                                 ▼
              直接回车 → 无时间的待办            输入"明天10点交周报"
                                                     │
                                            （P1：自然语言解析）
                                                     ▼
                                            自动填 due_at + 提醒
```

**关键设计：手动录入必须能"一句话完成"。** 弹出完整表单（标题/描述/时间/优先级/提醒规则）是反模式，会让记录成本回到传统 app 的水平。首版用一个输入框 + 两个快捷时间按钮（今天晚些 / 明天上午）。

### 6.2 提醒 → 追问 → 完成的完整时序

```
时刻       桌宠                     系统                      数据
────────────────────────────────────────────────────────────────────
T-30m      idle                     -                         -
T-0        remind 冒泡              Windows Toast              fire_count+1
           "写周报，到点了"                                     last_fired_at=T
              │
              ├─ 用户点"已完成" ──→ celebrate → idle      status=done
              │                                            completed_at=T
              │
              ├─ 用户点"稍后" ────→ idle                next_fire_at=T+15m
              │
              └─ 8s 无响应 ──────→ idle                 （等下次 tick 重发一次）
                                       
T+20m      think 冒泡               -                         progress_log
           "周报开始写了吗？"                                  answer=?
              │
              ├─ "进行中" ───────→ idle                 继续按原规则追问
              ├─ "还没开始" ─────→ idle                 追问频率降级
              └─ "已完成" ───────→ celebrate            status=done
```

### 6.3 追问的时机策略（不是固定间隔）

| 任务状态 | 追问时机 |
|---|---|
| 有 deadline，未开始 | deadline 前 50% / 80% / 95% 各一次 |
| 有 deadline，已标记"进行中" | 只在 80% 和 95% 各一次（已在做了，别烦） |
| 无 deadline，有开始时间 | 开始后 1h / 4h / 24h |
| 连续 2 次回答"还没开始" | 降级为每天 09:30 一次 |
| 已逾期 | 每天 09:30 一次，直到完成或手动静音 |
| 夜间 23:00–07:00 | 一律不追问，顺延到 08:30 |

> 这套规则是纯函数 `plan_progress_checks(task) -> Vec<Instant>`，可以脱离 UI 单测。

## 7. AI 接入带来的交互范式变化

这是本产品**唯一真正的护城河**，值得单独说清楚。

传统待办：**人 → 界面 → 数据**
本产品：**人 → AI → 数据**，界面降级为"通知出口"

这意味着几个反直觉的设计决策：

| 决策 | 常规做法 | 本产品 |
|---|---|---|
| 主入口 | 应用界面 | AI 对话 |
| 界面职责 | 增删改查全包 | 只看 + 应急修改 |
| 数据校验 | 界面层校验 | repository 层校验（AI 和人都走同一套） |
| 时间格式 | 界面控件 | ISO 8601 + 时区，AI 直接生成 |
| 冲突处理 | 用户手动解决 | 最后写入者胜 + 事件日志可追溯 |

**推论**：MCP 工具的设计质量，比界面美观度更决定这个产品的成败。工具描述要让 AI 一看就知道什么时候该调、参数怎么填。

## 8. MVP 范围

### P0 —— 必须做，缺一个产品就不成立

| 模块 | 内容 |
|---|---|
| 桌宠窗口 | 透明、无边框、置顶、可拖拽、位置记忆、托盘常驻 |
| 宠物形象 | 鲸鱼娘位图立绘（6 张覆盖 7 个状态），含呼吸缩放与眨眼 |
| 待办 CRUD | 面板内增删改查、完成、软删除 |
| 提醒引擎 | 单次定时提醒、tick 扫描、休眠补偿、去重 |
| 追问引擎 | 按 deadline 倒推的追问计划、三个快捷回答 |
| MCP Server | 7 个工具：list / get / create / update / complete / delete / brief |
| 数据层 | SQLite + WAL + 迁移 + repository 单点出口 |
| 开机自启 | 默认开启，可在设置关闭 |

### P1 —— 显著提升体验，但不阻塞发布

- 全局快捷键唤起快速添加（`Alt+Space`）
- 自然语言时间解析（"明天下午三点"）
- 面板搜索与筛选
- 提醒音效开关
- AI 写入后的桌宠确认气泡
- 逾期任务在面板高亮 + 桌宠表情变化

### P2 —— 明确推迟

- 多设备同步
- 日历视图 / 看板视图
- Live2D 模型替换（表现力升级，需重新授权）
- 全屏透明层 + 像素级命中（宠物可在屏幕任意位置移动）
- Windows 计划任务兜底（GUI 未运行时的提醒）
- 数据导出 / 导入
- 番茄钟、习惯打卡

**明确不做**：账号体系、协作、分享、移动端。

## 9. 里程碑

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| M1 骨架 | Tauri 项目跑起来，透明窗口 + 鲸鱼娘立绘站上桌面 | 双击能展开空面板，托盘可退出 |
| M2 数据 | SQLite + repository + 迁移跑通 | 面板能增删改查，重启数据还在 |
| M3 提醒 | 调度器 + 气泡提醒 | 设 1 分钟后的提醒，到点准确冒泡 |
| M4 MCP | `--mcp` 分流 + 7 个工具 | Claude Desktop 里能建任务，桌宠面板立刻看到 |
| M5 追问 | 追问计划 + 三按钮回答 | 到点追问，回答后频率按规则变化 |
| M6 打磨 | 动画、音效、自启、打包 | 生成 NSIS 安装包，装完能开机自启 |

**M1–M4 是主干，任何一项卡住都先解决它，不要并行铺 P1 功能。**

## 10. 待你确认的开放问题

1. ~~**鲸鱼娘形象的具体风格**~~ —— **已定**：复用 Q 版鲸鱼女仆娘立绘，见 [04-pet-character-design.md](04-pet-character-design.md)。
2. **追问的语气**——中性（"周报开始写了吗"）还是带点拟人性格（"周报还没动哦，要我盯着你吗"）？后者更有记忆点，但有人会烦。
3. **默认追问强度**——激进（多次追问）还是克制（只在截止前问一次）？建议默认克制，可在设置调。
4. **托盘常驻 vs 完全隐藏**——是否允许用户彻底关掉桌宠只留后台？
