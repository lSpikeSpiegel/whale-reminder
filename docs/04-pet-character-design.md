## 3. 素材处理

### 3.1 处理脚本

```bash
# 需要 Pillow
python tools/prepare-art.py \
  --src <原仓库>/desktop-pet/art \
  --out assets/pet \
  --icon <原仓库>/icon.png
```

脚本做四件事：

1. **按 alpha 通道裁出可见包围盒**，去掉原图四周的大量留白
2. **等比缩放到 352×352 内**（contain，不拉伸）
3. **底部对齐 + 水平居中**——保证切换状态时脚底基线不跳动
4. **四周留 3% 安全边距**——给呼吸缩放（1.0→1.03）留余量，否则头发会被窗口裁掉

### 3.2 体积

| | 原始 PNG | 处理后 WebP |
|---|---|---|
| 单张 | 1.4 – 1.9 MB | 26 – 35 KB |
| 11 张合计 | **约 16 MB** | **345 KB** |

压缩比约 46 倍。质量 88 + LANCZOS 缩放，肉眼无明显损失。

### 3.3 输出规格

| 项 | 值 |
|---|---|
| 画布 | 352 × 352（显示 176 × 176 的 2x，适配 150% DPI 缩放） |
| 格式 | WebP，quality 88 |
| 对齐 | 底部对齐、水平居中、四周 3% 边距 |

### 3.4 `meta.json`

脚本同时生成 `assets/pet/meta.json`，前端直接读取，不需要硬编码坐标：

```jsonc
{
  "canvas": 352,
  "displaySize": 176,
  "poses": {
    "front": {
      "file": "front.webp",
      "drawRect": { "x": 30, "y": 11, "w": 291, "h": 330 },
      "eyes": {
        "y": 175.58,      // 眼睛中心 Y
        "height": 24.94,  // 单眼高度
        "width": 43.65,   // 单眼宽度
        "leftX": 107.12,  // 左眼中心 X
        "rightX": 211.88  // 右眼中心 X
      }
    }
  }
}
```

**`eyes` 是眨眼动画的关键**。这组坐标来自原仓库 `Program.cs` 里 `Pose` 类的归一化参数（`eyeY / eyeHeight / eyeWidth / leftEyeX / rightEyeX`），脚本把它们从原图坐标系映射到了 352 画布上。目前只有 `front` 和 `side` 有有效值，其余状态不做眨眼。

## 4. 状态映射

产品需要 7 个状态，素材有 11 张，映射如下：

| 产品状态 | 立绘 | 触发条件 | 动画 |
|---|---|---|---|
| `idle` | **front** | 默认，无事件 | 呼吸缩放 + 随机眨眼 |
| `react` | **front** | 鼠标移入 | 上浮 4px + 快速眨眼一次 |
| `remind` | **working** | 提醒触发 | 切图 + 气泡弹出 |
| `think` | **thinking** | 追问进度 | 轻微前倾 + 气泡弹出 |
| `sleep` | **sleep** | 23:00–07:00 或无操作 30min | 呼吸放缓至 8s 周期 |
| `celebrate` | **playing** | 任务完成 | 跳跃 2 次 + SVG 撒花 |
| `drag` | **side** | 拖拽中 | 随移动方向倾斜 ±6° |

**MVP 用 6 张**：`front` / `working` / `thinking` / `sleep` / `playing` / `side`。

其余 5 张的处置：

| 立绘 | 处置 | 说明 |
|---|---|---|
| `slacking` | P1 | 无操作超过 30 分钟，坐下打哈欠摸鱼 |
| `bored` | P1 | 连续 3 天有逾期任务未处理，抱膝委屈 |
| `daydreaming` | P1 | 空闲但非睡眠时段，侧坐发呆 |
| `eating` | P2 | 彩蛋：一天完成 5 项后喂食 |
| `back` | **不用** | 无背面视角需求 |

> **关于 `working` 的尺寸差异**：`working` 自带桌椅纸笔的完整场景，包围盒接近正方形（1233×1226），缩放后**角色本体比 `front` 小约 25%**。经确认这个跳变可接受——提醒时切到"坐下来开始干活"的画面，语义上比单纯抖动强得多，尺寸变化反而强化了"从待机进入工作"的转换感。
>
> 缓解手段：切图时用 180ms 交叉淡入 + 轻微下移（`translateY(6px) → 0`），把硬切变成"坐下"的动势，弱化尺寸突变。

## 5. 动画方案（SVG 特效层）

立绘是位图，不能做骨骼动画。采用**位图打底 + 特效层叠加**，这是位图桌宠的主流做法，也是本项目的选定方案。

### 5.1 呼吸

```css
@keyframes breathe {
  0%, 100% { transform: scale(1) translateY(0); }
  50%      { transform: scale(1.015) translateY(-2px); }
}
.pet-img { animation: breathe 4s ease-in-out infinite; }
```

`scale` 上限 1.015 配合 3% 边距，不会裁切。睡眠状态把周期改成 8s，幅度减半。

### 5.2 眨眼

在立绘上方叠一层绝对定位的 SVG，用 `meta.json` 的 `eyes` 坐标画两条闭合眼线，周期性闪现：

```
眨眼周期：每 3–6s 随机一次，持续 120ms
实现：两个 <ellipse>，fill 用深蓝 #19234C，
      默认 opacity: 0，眨眼时 0 → 1 → 0
位置：leftX / rightX ± width/2，y ± height/2
```

**只对 `front` 生效**。其他状态立绘本身已有表情，叠加会错位。

### 5.3 状态切换

立绘切换用**交叉淡入**而不是硬切，避免"啪"一下换人：

```css
.pet-img { transition: opacity 180ms ease; }
/* 切换时：旧图 opacity → 0，新图 opacity → 1，叠 180ms */
```

配合 `preload`：启动时把 MVP 用到的 6 张全部 `new Image()` 预加载，避免首次切状态闪白。

> `front → working` 这一跳除了淡入，额外加 `translateY(6px) → 0` 的下移，把"角色变小"包装成"坐下来"的动势，而不是单纯缩放突变。

### 5.4 完成撒花

`celebrate` 状态叠加一层 SVG 粒子：8–12 个小圆点/小鲸鱼图标，从角色中心向上抛射后受重力落下，1.2s 结束。颜色取 `#4B8BDC` / `#C9A227` / `#FBFBFC`。

### 5.5 拖拽倾斜

```js
// 根据鼠标水平速度计算倾斜角，限制 ±6°
rotate = clamp(vx * 0.5, -6, 6)
```
松手后 200ms 缓动回正。

## 6. 窗口与命中测试

| 项 | 值 |
|---|---|
| 窗口尺寸 | 176 × 176（逻辑像素） |
| 内容尺寸 | 352 × 352（2x 素材） |
| 边框 | 无 |
| 背景 | 全透明 |
| 层级 | 置顶（`alwaysOnTop`） |
| 任务栏 | 不显示（`skipTaskbar`） |

**关于点击穿透的取舍**：

参考仓库用 `WS_EX_LAYERED + UpdateLayeredWindow` 提交完整 ARGB 表面，Windows 会对 alpha=0 的区域自动穿透，做到**像素级命中**。Tauri 走 WebView2 渲染，拿不到这条路径。

本项目采用**包围盒裁剪**：立绘已经裁到紧包围盒，窗口几乎贴着角色轮廓，只有四个角有少量透明区域会挡鼠标。实测体验差异很小，换来的是留在 Tauri 里、不用写 Win32 渲染循环。

> 如果后续觉得四角挡鼠标影响体验，升级路径是把桌宠本体改成 Rust 原生分层窗口（`windows` crate + `UpdateLayeredWindow`），气泡和面板仍走 WebView2。这个改动只影响渲染层，不影响任何业务代码。

## 7. 气泡与面板视觉规范

### 7.1 气泡

```
┌────────────────────────────┐  ← 白底 #FBFBFC，圆角 16
│ 写周报                     │  ← 15px / 500 / #19234C
│ 距截止还有 25 分钟          │  ← 13px / 400 / #37447D
│                            │
│ [ 已完成 ]   [ 稍后 ]      │  ← 主按钮 #355CB6 白字
└────────────────────────────┘     次按钮 透明底 + #355CB6 边框
         ▲
    小三角指向角色（8px）
```

| 元素 | 规格 |
|---|---|
| 宽度 | 自适应，最小 180，最大 260 |
| 圆角 | 16px |
| 阴影 | `0 4px 16px rgba(25,35,76,0.12)` |
| 内边距 | 14px 16px |
| 主按钮 | 背景 `#355CB6`，文字白，圆角 10，高 32 |
| 次按钮 | 背景透明，边框 1px `#355CB6`，文字 `#355CB6` |
| 出现动画 | `translateY(6px) + opacity 0→1`，180ms |

### 7.2 面板

沿用同一套色板：

| 元素 | 规格 |
|---|---|
| 背景 | `#FBFBFC` |
| 卡片 | `#FFFFFF`，边框 `#DFDFEB`，圆角 12 |
| 标题 | 15px / 500 / `#19234C` |
| 正文 | 13px / 400 / `#37447D` |
| 逾期标记 | `#A32D2D`（红，仅用于逾期，不用于其他） |
| 完成态 | 标题加删除线 + `#919DC6` |
| 强调 | `#355CB6` |

> **注意**：`#A32D2D` 这个红是唯一偏离角色配色的地方。逾期必须足够刺眼，不能为了配色统一而牺牲信息传达。

## 8. 已知问题

| 问题 | 影响 | 处理 |
|---|---|---|
| `thinking` 自带 "?" 气泡、`sleep` 自带 "zzz" | 与系统气泡可能视觉重叠 | 接受。`?` 在左上、`zzz` 在右上，系统气泡从右侧弹出可错开；且 `sleep` 期间本就不弹提醒 |
| `working` 角色本体比 `front` 小约 25% | 切到提醒状态时有视觉跳变 | 已确认可接受；切图用 180ms 交叉淡入 + 下移动势缓解 |
| 11 张立绘风格统一，但**只有 front 有眨眼坐标** | 其他状态看起来"不动" | 靠呼吸缩放补偿；P1 可手工标定其余立绘的眼睛坐标 |
| 位图无法做肢体动画 | 表达力上限低于 Live2D | 靠状态数量和特效层弥补；这是选 PNG 方案的既定代价 |
| 立绘边缘有轻微抗锯齿白边 | 在深色桌面背景下可能可见 | WebP 压缩时保留 alpha，暂不处理；若明显再对边缘做 alpha 羽化 |
