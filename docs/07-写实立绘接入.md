# Whale Reminder · 写实立绘接入

> 2026-11-13
> 素材：DeepSeek-chan 免费 Live2D 模型 + 分层 PSD（作者：神谷凌子 / 霓虹猫_NeonNeko）
> 结论：**先用 PSD 导静态立绘，Live2D 运行时留作下一阶段**。下面是为什么，以及真要做时怎么做。

---

## 1. 这套素材里有什么

| 文件 | 体积 | 说明 |
|---|---|---|
| `大肥鱼.moc3` | 15.7 MB | 模型本体，二进制，只有 Cubism Core 能读 |
| `大肥鱼.4096/texture_0*.png` | 45.6 MB | 5 张 4096² 图集 |
| `大肥鱼.physics3.json` | 217 KB | 头发 / 裙摆 / 尾巴的物理摆动 |
| `Animation/IDLE.motion3.json` | 35 KB | 待机动作（呼吸、轻微摇晃） |
| `Animation/*切*.motion3.json` | 2 KB × 7 | 举手 / 竖食指 / 狗尾草 的切换动作 |
| `Exp3/*.exp3.json` | 200 B × 24 | 表情：脸红、爱心眼、圈圈眼、流泪、＞＜、黑脸… |
| `psd/大肥鱼公皮分享拆分.psd` | 131 MB | 3749×7697 分层全身图，754 个图层 |

关键点：**能直接变成位图的只有 PSD**。moc3 和贴图必须经过 Cubism 运行时才能出画面。

## 2. 已落地：PSD → 静态立绘集

### 2.1 为什么是「全身 + 只换表情」

- **全身**：9 头身立绘在 176px 窗口里脸只有 18px，所以写实版**不用 176²，单独一个
  172×340 的窗口**（脸约 46px，和 Q 版一个量级）。窗口比例必须和素材严格一致，
  否则 `object-fit: contain` 会在四周留透明边。换风格时窗口以底边中点为锚变化，
  脚不往上跳；贴着边就重新吸附。
- **只换表情**：PSD 的 `动作` 组（竖食指 / 举手 / 狗尾草）只补了手和袖口，
  原来的两条手臂还留在身体上，直接叠会变成三只手。要用得先隐藏 `手←` `手→` 再整体重合成，
  而 psd-tools 重合成 750 层 × 28MP 慢到不可用（实测 10 分钟没跑完）。
- 姿势变化留给 CSS：呼吸、点头、蹦跳、摇晃本来就是 `.pet--xxx` 那套 keyframes 干的，
  写实立绘一样吃得到。

### 2.2 生成

```bash
pip install psd-tools
python tools/prepare-real-art.py              # 全身（默认），8 张 344×680 WebP，约 62 KB/张
python tools/prepare-real-art.py --keep 0.42  # 只要上半身（记得同时改窗口尺寸）
python tools/prepare-real-art.py --height 720
```

输出高度取窗口高的 **2 倍**（340 → 680），200% 缩放下正好一个像素对一个像素。

脚本做的事：`psd.composite()` 拿默认站姿（PSD 里 `表情`/`动作` 组默认是关的），
再把指定表情组的子层按顺序 alpha 叠上去。因为共用同一张底图，五个变体的身体、
光影、衣褶完全一致，切换时不会跳。

### 2.3 数据流

```
settings.json {"pet_style":"real"}
      │
      ├─ get_settings ──→ App.tsx PetView.style ──→ Pet.tsx
      │                                        └─→ loadPetMeta("real") → /pet-real/meta.json
      └─ set_pet_style ──改窗口尺寸──emit "pet://style"──→ 桌宠立刻换图（不用重启）
```

`Pet.tsx` 不再假设「动作名 = 文件名」，一律走 `meta.poses[pose].file`——
写实素材里 `think` 和 `poke` 都指向 `squint.webp`，硬拼路径会 404。

### 2.4 动作映射

| 动作 | Q 版（归档） | 写实 |
|---|---|---|
| idle / react / doze / sleep / work / daydream / drag / peek | front / side / sleep / working… | front |
| pat 摸头 | front + CSS 腮红 | blush |
| poke 戳 / think 沉思 | front / thinking | squint |
| happy 撒欢 / eat 吃点心 | playing / eating | heart |
| bored 无聊 | bored | dizzy |
| slack 摸鱼 | slacking | front |
| **angry 连戳 5 下** | bored（借用） | gloom |
| **smug 连摸 3 下** | playing（借用） | smug |
| **sad 撞到屏幕边** | bored（借用） | tears |

写实版没有侧身图，贴边时靠 `scaleX(-1)` 镜像表达朝向。
Q 版那三行标「借用」的，是因为它已经归档、没有新素材，只能拿最接近的姿势顶一下。

### 2.5 素材到底还支持什么

PSD 里能用的就两块：

| 组 | 内容 | 用了吗 |
|---|---|---|
| `表情` | 脸红 / 爱心眼 / 圈圈眼 / ><眼 / 屑屑眼 / 脸黑 / 流泪，共 7 组 | **全用了**（8 张立绘，含默认站姿） |
| `动作` | 竖食指 / 举手 / 狗尾草，共 3 组 | **没法用**，原因见下 |

`动作` 组只补了「手 + 袖口」，原来的两条手臂还画在身体上——直接叠会变成三只手。
要用得先把 `手←` `手→` 隐藏再整体重合成，而 psd-tools 的合成器对 750 层 × 28MP
的重算是分钟级的：实测 `composite(force=True)` **13 分钟没跑完**，加 `viewport`
限制到手臂那一块也一样慢（它仍然逐层解码）。自己写合成器倒是 4.7 秒能出图，
但 PSD 里有 71 个剪切图层、54 个正片叠底、3 个线性减淡，纯 alpha 叠加的结果和
原图差 115/255——等于要重写一个 PSD 合成引擎，不值得。

**结论**：静态路线上，表情就是这套素材的上限。想要「举手 / 竖食指 / 叼草」这种
姿势变化，只能上 Live2D 运行时（第 3 节）。

## 3. 下一阶段：接 Live2D 运行时

> **已落地（2026-11-16）**：走的就是下面选定的第二条路——官方 Cubism Web Framework 原样拷进
> `src/live2d/cubism/`，`src/live2d/WhaleModel.ts` 自己写渲染循环，没有 pixi。
> 0.7.0 起动态立绘是默认形态、没有开关：启动时探一下 `assets/live2d/textures/` 在不在
> （见 `src/live2d/availability.ts`），在就用模型，不在就退回静态图。
>
> 落地时踩到的坑，记在这里免得下次重踩：
>
> 1. **gl 视口得自己设**。框架不会设，遮罩流程只是把视口改成离屏尺寸再"恢复"，
>    而那个"上一次"是上下文创建时的旧值——不调 `setRenderState`，绘制会一直落在
>    画布左下角的一小块里（还按旧视口的长宽比拉扁）。
> 2. **落位要按包围盒，并且要用实际像素校一次**。模型画布是 1×2.053，比角色大得多；
>    而顶点包围盒又比着色范围宽 25%（有顶点摊得宽的 drawable）。所以先按顶点画一帧、
>    量出真实像素、再校正一次，见 `src/live2d/fit.ts`（两个函数都有单测）。
> 3. **窗口不跟着模型改**：角色实测宽高比 0.43，竖窗 172×340 本来就合适。
>
> 体积上：**没有降贴图分辨率**（5×4096² 原样加载）。理由是懒加载 + 只在用户显式开启时
> 才下载，常驻内存只在开着的这段时间里涨，砍到 1024² 反而会让脸糊。

如果哪天嫌「只有表情没有姿势」，唯一的路是把 moc3 跑起来。工作量比静态立绘大一个量级，
但换来的是真呼吸、真眨眼、头发和裙摆的物理摆动。

### 3.1 缺的那块拼图

Cubism Core（`live2dcubismcore.min.js` / `.wasm`）**不在 npm 上**，只能从
[Cubism SDK for Web](https://www.live2d.com/en/sdk/download/web/) 下载并同意条款后手动放进
`src/vendor/`。上层加载器二选一：

- `pixi-live2d-display` + `pixi.js`：开箱即用，但要拖进 pixi（约 400 KB gzip）。
- 官方 Cubism Web Framework（TS 源码）：零额外依赖，但要自己写渲染循环和窗口适配。

桌宠窗口是 176×176 的透明窗口，用 WebGL 画布铺满即可，不需要 pixi 的整套场景图——
**倾向第二个**，和「不引第三方运行时」的项目约定一致。

### 3.2 体积必须先砍

| 项 | 原样 | 处理 |
|---|---|---|
| 贴图解码后显存 | 5 × 4096² × 4B = **335 MB** | 降到 1024² → 21 MB（176px 窗口根本看不出差别） |
| moc3 | 15.7 MB | 没法压，只能懒加载 |
| physics3 | 217 KB | 保留 |
| IDLE motion | 35 KB | 保留 |

335 MB 显存对一个常驻桌宠是不可接受的，**不降采样就别接**。
降采样用 Cubism Editor 的「纹理图集」重导，或直接把 PNG 缩到 1024 后改 `model3.json`
里的贴图路径（UV 是归一化的，换分辨率不用改模型）。

### 3.3 参数映射

`PetActivity` 那 15 个状态可以直接对到 Cubism 参数上，比现在做表情图更省事：

| 动作 | 参数 |
|---|---|
| idle | 播 `IDLE.motion3.json` 循环 |
| react 抬头 | `ParamAngleY` +10，`ParamBodyAngleY` +5 |
| pat 摸头 | `ParamAngleY` −8 + 表情 `脸红` |
| poke 戳 | `ParamBodyAngleZ` 摆动 + 表情 `＞＜` |
| happy | 表情 `爱心眼` + `ParamBodyAngleZ` 正弦 |
| bored | 表情 `圈圈眼` + `流冷汗` |
| sleep / doze | `ParamEyeLOpen` = `ParamEyeROpen` = 0，播 `脱捕` 动作 |
| drag | 保持垂直，不随位移倾斜（`--tilt` 已移除） |

表情走 `Exp3/*.exp3.json`，和现在「动作 → 立绘」是同一张映射表的形状，
`ACTIVITY_POSE_REAL` 换成 `ACTIVITY_EXPRESSION` 就行。

### 3.4 风险

- **首帧延迟**：moc3 15.7 MB 要读盘 + 解析，冷启动会白一下。得先显示静态 `front.webp`，
  模型 ready 再淡入，失败就永远停在静态图（回退路径必须有）。
- **常驻开销**：WebGL 上下文 + 20 MB 贴图，比现在「一张 72 KB 的 WebP」贵得多。
  桌宠是开机自启、永远开着的进程，这笔账要认。
- **许可**：SDK 开发阶段免费；**发布**时个人 / 小规模事业者免签发布许可、免付费
  （「可扩展应用」除外，比如给第三方做皮套的追踪软件）。本应用是分发给终端用户的
  原生应用，属 Non-profit Content Plan（D 档）。真要发布前照着
  [官方流程](https://www.live2d.com/en/sdk/license/) 走一遍，别凭记忆。
